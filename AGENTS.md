# Project instructions

Read and follow [docs/GIT_WORKFLOW.md](docs/GIT_WORKFLOW.md) for every task in this repository. Inspect and preserve existing changes; synchronize each completed, verified, accepted logical change to the intended GitHub remote and verify the remote SHA, unless the task or policy explicitly prohibits pushing.

Read the current project specification and relevant verification/handover reports before implementation. Treat historical test counts and runtime snapshots as dated evidence, not current verification. Preserve source provenance and the distinction between documents, claims, evidence, incidents and Event Threads. Confidence and importance are separate; contextual similarity does not establish a causal relationship.

Git synchronization does not authorize deployment or historical data correction. Respect task-specific live-database and runtime restrictions.
